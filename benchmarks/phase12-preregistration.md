# Phase 12 pre-registration: scanner import + remediation race fix

Committed on 2026-11-26, **before** any Phase 12 code.
`git log -- benchmarks/phase12-preregistration.md` shows the order.

Phase 12 publishes **no measured benchmark number**. The user chose
correctness tests only. What is pre-registered here is:
- the behaviour;
- the exact tests that must exist and pass in CI before the phase counts
  as done.

Every test file used is generated by us. No third-party scan output is
committed.

## Part A: Nessus / OpenVAS import

**Input.** One XML file per request, body of
`POST /projects/{project_id}/imports`. The format is detected from the
root element:
- `NessusClientData_v2`: a Tenable `.nessus` v2 export;
- `report`, or `get_reports_response` wrapping a `report`: a
  Greenbone/OpenVAS XML report.

**Hostile-input rules.** The file is untrusted.
- It is parsed with `defusedxml`, and any DTD is refused. That blocks
  XXE, external entities and entity-expansion bombs: no DTD, no
  entities.
- Body size is capped at 20 MB; larger is rejected with 413.
- Report hosts are capped at 1,000, and per-file result items at
  100,000.
- Malformed XML, an unknown root, a host without a scan time, and a
  file over a count cap are each rejected with 400 and a clear message.
  Nothing is written.
- CVE ids must match `CVE-\d{4}-\d{4,7}`; anything else is dropped and
  counted. Ports must be 0–65535. Free-text fields are clamped to their
  column sizes.

**Host matching.** A report host is attached only to an existing
non-CIDR target of the same project.
- A match is the host's IP, report name or FQDN, compared
  case-insensitively with any trailing dot removed.
- An IP target wins over a hostname target.
- Unmatched hosts are skipped and listed in the response. No target is
  ever created by an import.
- Importing doesn't scan anything, so it doesn't require
  `authorization_confirmed`.

**Mapping.**
- One imported host becomes one `Scan`:
  - `config.scanner` = `nessus` or `openvas`;
  - `created_at` = the host's scan start time from the file, not the
    upload time.
- That scan also gets one `Asset`, one `Service` per port, and one
  `Finding` per (plugin/NVT result, CVE).
- A finding keeps the scanner's evidence: plugin id / NVT OID, name, the
  scanner's own severity, CVSS and QoD.
- `Finding.source` = `nessus` / `openvas` (`vulnsight` for its own
  scans).
- Results without a CVE, and informational (severity 0 / log) results,
  are counted and skipped.
- Imported findings then go through the same steps as a VulnSight scan,
  from the correlation stage on: KEV/EPSS enrichment, applicability,
  remediation sync, risk scoring and the report. The pipeline still has
  6 stages; an import enters at CORRELATING.
- **Confidence:**
  - OpenVAS: the result's QoD (0–100);
  - Nessus: a fixed, named constant, because Nessus has no per-result
    confidence. It is a first-pass judgment call, disclosed in the
    README.

**Merge.** Remediation items stay keyed by
(target, port, protocol, CVE).
- The same CVE on the same port from VulnSight and from an import is
  **one item**.
- `RemediationItem.sources` records every source that has reported it.

**Verification stays source-aware.** Absence is evidence only from a
scan that could have seen the CVE.
- A VulnSight rescan can verify an item by "CVE not matched" only when
  `vulnsight` is among the item's sources.
  - VulnSight cannot see CVEs that only Nessus's plugin checks detect,
    so its silence about them proves nothing.
- "Service not observed" (the port is closed while the host still
  shows open ports) applies to any source, but never to port 0. Nessus
  uses port 0 for host-level checks, which nmap can't observe.
- **An import never verifies anything.** Absence from an export can
  mean a narrower scan policy, a non-credentialed run, or a filtered
  export. It is not evidence of a fix.
  - Known consequence: an item reported only by Nessus, whose port stays
    open, is never auto-verified; only an analyst can move it, and
    "fixed" is as far as an analyst can take it. This is disclosed.

## Part B: remediation race fix

**The bug (disclosed in Phase 11).** Two scans of one target that
overlap can sync remediation out of order:
- an older scan finishing last could reopen an item that a newer scan
  had verified;
- two syncs creating the same new item at the same time would collide
  on the unique key and roll back.

**The fix.**
1. Sync locks the target row (`SELECT … FOR UPDATE`) for its whole
   transaction, so syncs of one target are serialized. The analyst
   PATCH locks the item row it changes.
2. Each target keeps a per-source watermark: the scan time of the newest
   synced scan from that source. A scan older than its source's
   watermark is skipped entirely and counted as `stale`.
3. Each item keeps `last_evaluated_at`: the scan time of the newest scan
   that saw it or verified it. No scan older than that may change the
   item. This covers cross-source order, e.g. importing a month-old
   Nessus file after a newer VulnSight scan.

"Scan time" is `Scan.created_at`: the queue time for VulnSight scans,
and the scan start time from the file for imports.

## Pre-registered tests (all must pass in CI)

**Race (Part B):**
- **R1.** An older scan of the same source, synced after a newer one,
  changes no item and is counted as `stale`.
- **R2.** A newer scan verifies an item, then an older scan that still
  saw the CVE is synced. The item stays `verified`.
- **R3.** An old import that saw a CVE, synced after a newer VulnSight
  scan verified it, leaves it `verified`. A newer import reopens it.
- **R4.** Real concurrency on the Postgres test DB: two sync calls for
  the same target, on separate sessions and threads, released by a
  barrier and both creating the same new item. Both return without an
  error, and exactly one item exists. Run 20 times in the test.
- **R5.** A unit test of the ordering rule itself (pure function).

**Import (Part A):**
- **I1.** Nessus parser: multi-host, a plugin with several CVEs, port 0,
  informational and no-CVE results skipped and counted, severity and
  CVSS mapped, scan time read from `HOST_START_TIMESTAMP` or
  `HOST_START`.
- **I2.** OpenVAS parser: CVEs from `<refs><ref type="cve">`, plus the
  older comma-separated `<cve>` element; QoD read; the `log` threat
  level skipped.
- **I3.** Hostile files rejected, with nothing written:
  - a DTD with an external entity (XXE);
  - a billion-laughs entity bomb;
  - malformed XML;
  - an unknown root;
  - a body over 20 MB (413);
  - over the host cap.
- **I4.** Field hygiene: invalid CVE ids dropped and counted, an
  out-of-range port rejected, overlong names clamped.
- **I5.** Host matching: IP, FQDN and report-name matches; IP preferred;
  unmatched hosts listed and skipped; no target created; CIDR targets
  never matched.
- **I6.** End to end through the API, with a VulnSight-sourced item
  already open for the same key: the import creates no duplicate, adds
  `nessus` to `sources`, gets KEV/EPSS-enriched findings, and ends with
  the scan `completed`.
- **I7.** Source-aware verification:
  - a VulnSight rescan doesn't verify a Nessus-only item whose port is
    still open;
  - it does verify one whose port closed;
  - port-0 items are never verified by a closed port;
  - an import never verifies.

**Done** means CI is green on the merge commit with every test above
present by name. The README lists each test's name next to its rule.

## Amendment 1 (2026-11-26, after the code, before the merge)

A fresh-eyes review of the implementation found two rules too loose. Both
changes tighten the rules; neither loosens any. They are committed here
before the fixing code.

1. **"Service not observed" needs a port VulnSight actually probes.**
   - nmap probes only TCP, top 1000 ports. So a closed-port verification
     must require that the item's (port, protocol) was seen open by an
     earlier VulnSight scan of the same target. That proves nmap probes
     it.
   - Otherwise an imported UDP item (e.g. 161/udp), or one on a port
     outside nmap's set, would be "verified" by every VulnSight scan,
     because nmap never looks there.
   - Port 0 stays excluded, as before.
   - I7 gains two tests: a UDP item, and a TCP port nmap never saw open.
     Neither is verified. The existing closed-port I7 test now first
     shows port 80 open in an earlier VulnSight scan.
2. **Report scan times are bounded.**
   - A host whose scan time is before 2000-01-01, or more than 1 day in
     the future, is rejected (400; nothing written).
   - A time up to 1 day in the future (clock skew, or Nessus's
     timezone-less `HOST_START` read as UTC) is clamped to the import
     time.
   - Without this, one future-dated file would set the watermark and
     items' last evaluation in the future and freeze the target's
     remediation until that date.
   - I3 gains a future-date case and a pre-2000 case.

Also fixed from the review, with no rule change:
- an unknown XML encoding now gets a 400, not a 500;
- the import task is idempotent and fails cleanly;
- the target lock is `FOR NO KEY UPDATE`, so it doesn't block inserts
  that reference the target;
- IPv6 targets are compared in normalized form;
- I6 now runs the real `finish_import_task`.
